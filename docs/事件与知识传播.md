# 事件、即时信号与知识传播

核对日期：2026-10-23。

| 组件 | 数据语义 | 当前行为 |
|---|---|---|
| `WorldEventBus` | 某时某地发生的环境事件 | 每维度环形缓冲，按村民游标和距离消费 |
| `VillageSignalBoard` | 集结、交易供需等即时请求 | 带时效的信号及其业务消费者 |
| `GossipChannel` | 可分享的资源位置知识 | 每次调用按概率单向传递至多一个特征锚点 |

## WorldEventBus

容量为 256，写入覆盖最早条目；缓冲在内存中。每村民持消费游标，每次慢更新默认最多读取 8 条，按区块曼哈顿距离过滤，默认半径 4 个区块。距离外事件同样推进游标。长期离线可能错过已覆盖事件，环形覆盖由事件数量决定，不能解释成固定时间 TTL。

当前枚举仅有 `BLOCK_CHANGED`、`ITEM_DROPPED`、`NEW_VILLAGER`。事件桥在方块放/破及实体加入等路径发布；`VillagerAgentManager.onWorldEvent` 对 `NEW_VILLAGER` 去重生成一次性 socialize 目标。另两类在该消费者中没有目标注入，方块索引维护和拾取由各自系统处理。实体加入事件的来源是否为加载恢复，需要按事件生产路径判断。

因此当前感知采用周期更新加有限事件接入。作物机会由局部扫描获取，战斗由战斗扫描及集结信号处理。

## GossipChannel

`tryGossip` 按 `gossip_chance`（默认 0.30）决定是否尝试传播，遍历讲述者的区块记忆，找到听者尚无的资源特征后复制一个代表锚点和访问时间。资源范围为矿类、FARMLAND、CROP、WATER；家具与建筑锚点不在此传播集合中。复制矿类时设置 `oreExpiryTick`，默认跨度 72000 ticks。

`SocializeSkill.chat` 在开始村民对话时调用 `tryGossip`，资源知识传播已接入社交路径。矿情报的到期值随记忆保存并供调试导出；当前传播选择没有读取该值过滤，也没有完整的到达后证伪消费路径，因此到期停止传播与采集证伪尚未形成闭环。关系意见传播则在 `VillagerSocialSystem`，与资源锚点复制是不同机制。

这套数据结构支持村民间知识差异，当前资源采集的实际选址仍以 `ResourceSensor` 的局部加载区域、暴露条件和站位路径为依据。
