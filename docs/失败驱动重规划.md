# 失败驱动重规划

核对日期：2026-10-23。入口为 `FailureRecoveryPlanner.handle`，由 `VillagerAgentManager.processGoals` 在无可用 handler 或技能 `BLOCKED/FAIL` 时调用。执行结果的保留、冷却和退出统一见 [主循环](事件驱动大脑与资源订单.md)。

## 失败表示与分发

`Failure` 记录 `reason`、`itemId`、`quantity`、`capability`、`requiredLevel`，挂在 `AgentGoal.lastFailure`。物品与工具缺口均用 `MISSING_ITEM`。

| 原因 | 当前处理 |
|---|---|
| `MISSING_ITEM` | 查已有产出目标 → 查已解锁配方 → 发布物资需求 |
| `NO_JOB_SITE` | 复用或创建 `find_job_site` 一次性目标，指定目标职业 |
| `NO_RECIPE` | 有物品 ID 时发布物资需求；无 ID 时记录记忆 |
| `CAPABILITY_TOO_LOW` | 记录需要的能力等级，等待训练等外部变化 |
| `NO_BED`、`BED_OCCUPIED`、`NOT_NIGHT`、`UNREACHABLE`、`UNKNOWN` | 记录失败记忆，由退出策略决定重试 |

枚举名表示可记录的原因；每个技能实际会产生哪些原因需看其 `execute`。例如睡眠的当前选择条件为疲劳。

## 缺物品的处理顺序

1. 遍历未完成目标的 `outcomeItems`，找到能产出所需物品且有 handler 的目标时，清除其冷却。方法名是 `boost`，方法体操作的是 `cooldownUntilTick`，priority 保持原值。
2. `NativeRecipeResolver.resolveRecipe` 有结果且 `SkillCraftCatalog.isUnlockedFor` 通过时，复用已有 craft 目标或创建 priority 6 的一次性 craft 目标，设置物品、数量、产出集合。
3. 其余情况调用 `ResourceWorkSystem.request`，以“当前库存 + 缺少数量”为目标库存，同时向 `VillageSignalBoard` 发布 `TRADE_WANT`。有配方时继续处理缺少材料，递归深度上限为 2。

去重通过现有目标、目标物品和信号板完成。`NO_JOB_SITE` 创建的目标 priority 为 7；已存在时清除冷却。恢复逻辑在服务端线程执行。

## 补货与获取物品

`RestockSkill` 遍历职业启动物资表，每项目标库存为 `min(8, supply.quantity)`。不足则请求资源订单并发布交易需求，返回 `WAITING`；全部满足则 `SUCCESS`。启动物资表在这里定义需求种类与数量，实际补货依靠真实供给。

`AcquireItemSkill` 的目标为 `targetItem` 和 `targetQuantity`。库存已满足时完成，并移除该作者的 `TRADE_WANT`；有已解锁配方时尝试直接消耗材料制作，成功后下一 tick 核对库存；材料不足时等待。没有可用制作路径时请求资源订单并等待。当前完成清理的范围是该作者全部 `TRADE_WANT`，维护多个并行求购目标时需考虑这个范围。

农民缺锄头的链路为：`FarmSkill` 上报物品缺口 → 恢复器复用产出目标或创建 craft/物资需求 → 调度器选择可行目标 → 背包获得工具后农业步骤重试。每一步的完成证据是库存和世界状态。
