## Village market and tree implementation

- `ai/VillageRegistry.java`: persisted vanilla village bounds and affiliation, loaded structure reads.
- `ai/VillageMarkets.java`: one board per village origin and dimension.
- `ai/BarterMath.java`, `ai/BarterExchange.java`: unused compatibility barter code; villager cooperation is free.
- `ai/SupplyPolicy.java`: exact/category request matching, food units, tool ranking and delivery stack selection.
- `ai/CooperativeSupply.java`: request validation, tool retention, shareable stock, board inspection, delivery reservations and receipt accounting.
- `ai/BoardMemory.java`: per-villager board snapshot refreshed only by physical board reads.
- `ai/CooperativeSupplySkill.java`: `supply_request` request-linked, non-exclusive production and direct delivery.
- `ai/PaidProductionSkill.java`: retires legacy `produce_order` goals.
- `ai/work/TreeGraph.java`, `ai/work/TreeFelling.java`: memory selection, connected tree snapshot, timed protected removal.
- `ai/behavior/ResourceWorkSkill.java`: inert legacy compatibility tombstone.

## Call chain

`VillagerEventHandler.onWorldTick → tickAgents → slow updateAgent / per-tick processGoals → GoalScheduler → BehaviorExecutor.executeRoot → TaskExecution → skill.execute / executeChild → ActionLifecycle / GoalExitPolicy`. Combat, explicit building, economy, and debugging have separate tick entry points. Goal execution yields when non-goal-driven actions occupy the body.
