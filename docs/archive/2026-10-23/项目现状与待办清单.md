## 3. TODO 清单（按优先级）

### P0 / 高（正确性 / 明显缺口）
- [x] **G3 索引失效**：**已修（2026-08-16）**——活塞/爆炸/液体/命令（`/setblock /fill /clone`）均已接 `markDirty`。仅剩：命令放新床不播种、火灾/龙/凋灵自然破坏（低频，可选）。
- [x] **消费断层（HOME 回填）**：**已收口（2026-08-17）**——新增 `ai/behavior/` 技能系统（`VillagerSkill` + `BehaviorExecutor` + `SleepSkill`），村民睡觉改为纯程序化技能：`SleepSkill` 依次取 `MemoryModuleType.HOME` → `VillagerAgentData` 持久化的 home bed → `WorldStructureIndex.queryNear` 最近带床建筑（命中后把床记住到 `homeBedPos`，即"这是我家的床"），走到后 `startSleeping`。`VillagerActivitySystem.handleResting` 已委托 `SleepSkill.tickRest`（夜间由每日计划 `resting` 槽触发），`processGoals` 里的 `rest`/`sleep` 目标也走 `BehaviorExecutor` 派发。睡眠回血仍由 `tickSleepHealing` 接管。待用户 `gradlew compileJava` 验证。
- [x] **trade/socialize 目标空壳**：**已实现（2026-08-16）**——新增 `VillagerTradeSystem`（发起方 LLM 提案 → 接收方 LLM accept/reject/counter → 代码交换物品，支持以物易物/绿宝石通用货币 + 关系变化）；`executeSocializeGoal` 改为走到最近村民（对话由 `tickSocial` 触发）。
- [x] **RecipeRegistry 双轨收口**：**已收口（2026-08-16）**——`finalizeCrafting` 改用 `ProfessionCraftCatalog`+`NativeRecipeResolver`，`buildActionRequest` 同步；RecipeRegistry 仅剩死代码引用。

### P1 / 中
- [ ] **多智能体编排（完整黑板+事件总线）**：威胁分工「发现→号召→群殴」核心已落地（`VillageSignalBoard` + `wouldWinSolo` + `FLEE`）；剩余 `VillageBlackboard`/`VillageEventBus` 的其它事件——`NIGHT_FALLING`（回家）、`RESOURCE_SURPLUS`（招揽采集）、`VILLAGER_MISSING`（搜寻）、敲钟报警（Raid 专用）。设计见 `village_orchestration_design.md`。
- [x] **自主行为执行器 + 技能系统（todo→action 闭环）**：已实现（2026-08-17）——`ai/behavior/` 包：`VillagerSkill`(id/canHandle/execute 接口)、`SkillResult`(SUCCESS/RUNNING/BLOCKED/FAIL)、`BehaviorExecutor`(静态注册表 + 按 priority 定时派发，全程无 LLM)。`VillagerAgentManager.processGoals` 在 switch 前先让 `BehaviorExecutor` 拦截（由 `ModConfig.behavior_executor_interval_ticks`(默认20) 节流）；LLM 只负责增删/调权 goal 内容（`TodoParser`/`AgendaParser` 产出），不触发执行。首个落地技能 `SleepSkill` 收掉 P0 HOME 回填；`CraftSkill`/`MoveSkill`/`TradeSkill` 等可按同一接口后续接入。待用户 `gradlew compileJava` 验证。
- [ ] **检索增强记忆**：`MemoryStore` 类型化 + importance/recency/relevance 打分检索。设计见 `retrieval_memory_design.md`。
- [ ] **G4 backoff**：`processPending` 在周边 chunk 未加载时重新入队（而非出队丢弃），避免静态小区漏检。
- [x] **职业可制作物品 + 双路配方解析**：已实现（2026-08-17）——`ProfessionCraftCatalog` 保留 8 个原版无配方项（chainmail×4 / saddle / filled_map / quill / ender_pearl）作为 `usesCustomRecipe` 项，按职业+等级解锁；新增 `CustomRecipeRegistry`（运行时从 `config/villageragent/custom_recipes.json` 加载自定义配方）+ `ResolvedRecipe` 统一句柄 + `NativeRecipeResolver.resolveRecipe`（原版配方优先、自定义兜底）。`ActionValidator`/`VillagerActivitySystem`/`VillagerAgentManager` 三处消费侧由 `findRecipe` 改为 `resolveRecipe`，使"原版无配方但有自定义配方"的物品可正常制作。`cooked_beef` 等熔炼配方仍走原版路径。待用户 `gradlew compileJava` 验证。
- [ ] **E 溢出**：分水岭固有局限——洞连通有顶暗格时两盆地都合格；加"连通颈宽判定"（1×1 洞作隔断/壁橱，≥2 格才算门）。
- [ ] **通用采集**：挖矿/伐木/钓鱼等职业化采集（当前仅 farmer 收割 + `ItemAttractionSystem` 捡掉落物）。
- [x] **村民熟练度/经验系统 API**：已实现（2026-08-17）——`ai/proficiency/` 包：`ProficiencyLevelTable`（阈值表数据驱动，默认照抄原版 0/10/70/150/250）、`VillagerProficiency`（累计 xp + 等级推导 + 增/减/查询 API + 推升式 `syncToVanilla`）、`VillagerProficiencyProvider`（Capability 自动持久化）、`ProficiencyCapability`（注册 + 静态门面 `addXp/removeXp/getXp/getLevel/syncToVanilla`）、`ProficiencyEvents`（`AttachCapabilitiesEvent<Entity>` 给每个 `VillagerEntity` 挂 capability）。`setup()` 调 `register()`；`ModConfig` 保留 `proficiency_sync_to_vanilla`(默认true)（等级数/每级经验已移到 `config/villageragent/proficiency.json`）。**所有可改数据统一抽到 `config/villageragent/` 子文件夹**（见下条）。本次**仅 API**；加经验的行为（制作/与玩家&村民交易/吸怪掉落）待后续接入，调用 `ProficiencyCapability.addXp(villager, n)` 即可。待用户 `gradlew compileJava` 验证。
- [x] **`config/villageragent/` 可改子文件夹（一个大类一个 JSON）**：已实现（2026-08-17）——`ai/config/VillagerAgentConfigDir` 统一管理。启动时（仅当文件不存在）把 jar 内置默认 JSON 抽到 `<游戏>/config/villageragent/` 下供玩家/整合包/其它模组修改，之后一律读外置文件、缺失才回退 classpath。**约定：一个大类一个 JSON**，当前两类：`custom_recipes.json`（自定义配方）、`proficiency.json`（等级数 + 每级累计经验 + `unlocks` 字段：按职业+等级追加可制作物品，默认 `{}` 纯内置目录）。重复拆小文件的 `proficiency_unlocks.json` / `proficiency_unlocks.example.json` 已合并删去。`.toml`（`ModConfig` 生成于 `config/` 根，Forge 约定）**只放行为开关**（enable 标志、半径、节拍等），不放游戏数据表——数据表一律走 JSON。
