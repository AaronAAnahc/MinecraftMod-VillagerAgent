> 历史文档：当前执行链路已于 2026-10-09 调整，请以[事件驱动大脑与资源订单](事件驱动大脑与资源订单.md)和源码为准。本文的日程、昼夜权重、执行节流与部分待办状态可能已失效。

> 源码快照：2026-09-03 · 包路径 `com.github.AaronAA0721.villageragent`
> 文中所有类名、常量、阈值均取自 `src/main/java/...`，可直接对照阅读。

## 0. 一句话概括

**双轨架构：LLM 是「作者」，规则代码是「工人」。**

LLM 只负责产出/编辑**意图**（写 todo、写日程、写台词、写长期承诺），
**从不直接驱动村民的每一帧动作**。
每帧的动作由一条完全确定性、无 LLM 的管线完成：

```
感知 → 目标池(AgentGoal 列表) → 调度(GoalScheduler) → 技能(12 个 VillagerSkill)
     → 动作(VillagerAction + 原版导航) → 失败记录(Failure) → 重规划(FailureRecoveryPlanner)
```

这样设计的原因写在 `BehaviorExecutor` 的类注释里：把 LLM 的延迟、费用、限流**完全挡在 per-tick 动作路径之外**。LLM 挂了，村民照样耕地、睡觉、补货；只是不再"想新点子"。

## 2. 六条 tick 循环（挂载点）

全部由 `VillagerEventHandler#onWorldTick`（`TickEvent.WorldTickEvent`，`Phase.END`，服务端）驱动：

| # | 入口 | 内部节流 | 干什么 | 开关 |
|---|---|---|---|---|
| 1 | `tickAgents` | 每村民 `AGENT_THINK_INTERVAL`（默认 **100 tick ≈ 5 s**） | 日程 → 感知刷新 → 活动 → 需求 → 能力衰减 → **processGoals（大脑主循环）** | `enable_ai_agents` |
| 2 | `tickCombat` | 战斗中 2 tick，空闲扫描 10 tick | 找威胁 → 打得过就打 / 打不过就边跑边喊人 → 人够了一起上 | `enable_ai_agents` + `enable_world_interaction` |
| 3 | `tickBuilding` | 每 tick（`BUILD_BLOCK_INTERVAL` 控制每块间隔） | 单块放置/破坏、推进 `BuildJob` 多块建造 | 额外 `enable_building` |
| 4 | `tickSocial` | 200 tick（≈10 s），且非夜间 | 找空闲且近（≤5 格）的另一村民 → LLM 生成 4 行对话 | `enable_villager_social` |
| 5 | `tickThoughts` | 扫描 40 tick，每人冷却 6000 tick（5 MC 分钟），玩家需在 20 格内 | LLM 内心独白（可附带 `GOAL:` 指令） | `enable_villager_thoughts`（**默认关闭**） |
| 6 | `tickGreeting` | 扫描间隔可配，玩家需在 8 格内，每人每玩家冷却 2400 tick | 概率性打招呼（被周围人数稀释、按熟悉度衰减） | `enable_villager_chat` |

另外每 tick 还跑：`VillagerEconomySystem.tickEconomy`（无 LLM 的供需撮合）、`DebugSync.tick`（调试叠加层）、`ItemAttractionSystem`（物品吸附拾取）。

## 3. 慢 tick：一个村民的一次"思考"

`VillagerAgentManager#updateAgent`，按固定顺序：

1. **日程 planner**（`VillagerSchedulePlanner.tick`）
   - 黎明（dayTime < 2000）且今天没计划过 →
     ① `DeterministicPlanGenerator.generateRoutineGoals` 生成 3 条日常 goal；
     ② LLM 生成 `DailySchedule`（morning/afternoon/evening/night 四段，活动限定 farming/socializing/crafting/exploring/resting）；
     ③ `HarnessDecisionPlanner.decideDailyGoal` 让 LLM 再出一条结构化决策（默认开启）。
   - 黄昏（13000–15000）且当前无动作 → LLM 反思，可输出 `TODO:` 行 → 转成 goal。
2. **区块记忆更新**：每次慢 tick 都调 `updateChunkMemory`（只做 contains 判断，跨区块才采样）。
3. **环境快照刷新**：每 1200 tick（1 MC 分钟）重建 `environmentSummary`，存进 agent 供所有 prompt 使用。
4. **活动系统**（`VillagerActivitySystem.tick`，20 tick 节流）：把 `scheduledActivity` 翻成实际移动（exploring / resting / crafting）。
5. **需求系统**（`VillagerNeedsSystem.tick`，1200 tick 节流）：饥饿衰减、自动进食、夜间疲劳累积、重算心情。
6. **能力衰减**：每天一次 `capabilityPool.decayTo(today)` + 同步原版交易等级 + 重算解锁配方。
7. **processGoals** —— 真正的大脑主循环，见第 6~9 节。

## 4. 感知：环境摘要怎么来的

`VillagerVisionSystem.buildEnvironmentSummary()` 拼出一段自然语言，是所有 LLM prompt 的"眼睛"。三层：

| 层 | 来源 | 内容 |
|---|---|---|
| **Far（远）** | `ChunkMemory`（每村民私有，上限 512 个区块，超出按 saliency 驱逐） | 首次进入区块时 `ChunkContentSampler` 采样并打标签：forest / farmland / water / village / ore / lava；记住工作台、箱子、床的锚点；记住见过的敌对/动物数量 |
| **Mid（中）** | `WorldStructureIndex`（**全服共享、事件驱动、`WorldSavedData` 持久化**） | 半径 3 区块内的建筑（房屋、洞穴屋、玩家自建），按床为种子做洪泛 + 测地距离场分水岭分割 |
| **Near（近）** | `DetailedViewRecorder` + `FrustumCuller`（实时扫描） | 视锥内最多 4 个显著方块 + 敌对/动物/村民/玩家计数 |

再加上：时间（early morning…deep night）、天气、生物群系、精确坐标、朝向的 4 个区块"known/unknown"、记忆中所有区块列表。

索引维护是**事件驱动**的：`ChunkEvent.Load` 把区块内所有床投入队列；放/拆床、活塞、爆炸、流体、`/setblock /fill /clone` 都会触发失效重算。每 tick 只从队列里消费 `FLOODS_PER_TICK` 个洪泛，避免卡顿。

## 5. 状态：VillagerAgentData 里存了什么

| 组 | 字段 | 说明 |
|---|---|---|
| 身份 | `name` / `personality` / `profession` | 新建时先给本地兜底名字，异步 LLM 结果到达后覆盖 |
| 意图 | `goals`（≤10）/ `runningGoal` / `agendas`（`LongTermAgenda`） | goal 是短期 todo；agenda 是长期承诺（债务/求购/交易/泛型） |
| 执行 | `currentAction`（`VillagerAction`） / `currentActivity` / `buildJob` | `VillagerAction` 带类型、相位(SEARCHING/WALKING/ACTING/WAITING)、目标方块/实体、stuck 计数、`goalDriven` 标记 |
| 记忆 | `memories`（≥40 条触发 LLM 压缩）/ `conversationHistory`（1 MC 天过期，上限 40）/ `chunkMemories` | 压缩失败就直接砍掉最旧的 |
| 能力 | `capabilityPool`（9 个 `CapabilityId` 的 XP + 上次练习日） | FARMING / FISHING / SMITHING / BREWING / ENCHANTING / CRAFTING / GATHERING / SOCIAL / COMBAT |
| 需求 | `hunger`(0–100) / `fatigue`(0–100) / `mood`(5 档) | 心情由饥饿+疲劳+平均关系分推导 |
| 社会 | `relationships`（村民→分数）/ `playerReputation` | 对话按关系分决定语气，增益随关系递减；被赖账 3 次扣 5 点声望 |
| 经济 | `personalValueTable` | 首次交易时从职业模板深拷贝，之后每人独立漂移（绿宝石锚点 10.0） |
| 调度记账 | `lastThinkTime` / `lastExecutorTick` / `lastDayPlanned` / `lastDayReflected` / `lastGoalPruneDay` / `lastCapabilityDecayDay` / `blockedStreak` / `runningStreak` | 防重复、防抖、防卡死 |
| 空间 | `homeBedPos` / `reclaimState` / `farmRRIndex` / `farmFocus` / `farmTicks` | 这些是"技能是单例、状态必须落在 agent 上"的产物 |

## 6. 目标层：AgentGoal（todo）

### 6.1 字段

核心：`goalType`（`farm`/`craft`/`trade`/`socialize`/`rest`/`wander`/`move`/`goto`/`converse`/`gather`/`restock`/`acquire_item`…）、`description`、`priority`(1–10)、`importance`(1–10)、`lifecycle`、`outcomeItems`、`lastFailure`。

### 6.2 三种生命周期

| 生命周期 | 谁创建 | 完成/失败后 | 备注 |
|---|---|---|---|
| `REPEATABLE` | `RoutineScheduler`（只注入一次，幂等） | **永不移除**，进入冷却，到期自动重回候选池 | 常驻作息：`farm` / `restock` / `rest` / `wander` |
| `ONE_SHOT` | 其余全部来源 | 从列表移除 | 一次性任务 |
| `EXPIRING` | 带 `deadlineTick` 的 goal | 到点即丢弃 | |

`REPEATABLE` 目标自己携带**昼夜权重**（`dayWeight` / `nightWeight`），由 `seed()` 写入，调度器不再查全局表：

| 目标 | priority | 冷却 | 白天权重 | 夜间权重 | importance |
|---|---|---|---|---|---|
| `farm` | 5 | 1000 tick（≈50 s） | 6.0 | 0.0 | 6 |
| `restock` | 3 | 24000 tick（1 天） | 2.0 | 0.0 | 5 |
| `rest`（睡觉） | 8 | 0（由 SleepSkill 自己持有） | 0.0 | 8.0 | 7 |
| `wander` | 2 | 1000 tick | 1.0 | 1.0 | 2 |

昼夜判定：`dayTime ∈ [12541, 23458]` 为夜（对齐原版可睡觉窗口）。

### 6.3 目标的 8 个来源

| # | 来源 | 触发 | 说明 |
|---|---|---|---|
| 1 | `RoutineScheduler.ensureRepeatableGoals` | 每 tick（幂等，缺哪个补哪个） | 4 条常驻作息 |
| 2 | `DeterministicPlanGenerator` | 每天黎明 | **种子 = villagerId ⊕ day**，同一村民同一天的计划是可复现的。候选 = 职业池 ∪ 能力解锁池，权重 = 基础权重 ×(1 + 0.3×等级)，覆盖优先采样 3 条（farm 已被 RoutineScheduler 独占，此处剔除） |
| 3 | `HarnessDecisionPlanner` | 每天黎明（`harness_drive_daily_goal=true`） | LLM 返回 JSON `{"action","target","rationale"}`，经 `ActionValidator` 校验落地才入队，priority 6 |
| 4 | 内心独白 `GOAL:` 指令 | `enable_villager_thoughts=true` 时 | `GOAL: <type>|<desc>|<importance>[|<item>]` |
| 5 | 玩家聊天 `TODO:` 指令 | 玩家发消息时 | `GoalParser` 解析，玩家看不到这些行 |
| 6 | 傍晚反思 `TODO:` 指令 | 每天 13000–15000 | 把长期 agenda 重新表达成短期 todo（催债就是这里触发的） |
| 7 | 转职补货 | 失业 → 有职业的瞬间（`VillagerEventHandler`） | 清掉旧 restock goal、自动认领最近的工作站点、立一条 restock |
| 8 | `FailureRecoveryPlanner` | 技能 FAIL / 首次 BLOCKED | 见第 9 节 |

### 6.4 日常维护

- **每天一次**：`pruneLowImportanceGoals` —— `REPEATABLE` 永不随机剪枝；其余 importance ≤ 3 的各有 50% 概率被丢。
- **内心独白后**：50% 概率随机挑 1/4 的 goal `boostImportance()`（+1，封顶 10）—— 常想起的目标活过每天剪枝。
- 上限 `MAX_GOALS = 10`，超了走 `BrainLog.goalSkipped`。

## 7. 调度：GoalScheduler（每 tick 跑）

`processGoals` 中的调度段落，顺序如下：

1. **过期清理**：`expireGoals` 丢掉已完成的 ONE_SHOT 和过期的 EXPIRING（REPEATABLE 永远不在这里丢）。
2. **离相位让位**：正在跑的 REPEATABLE goal，若当前 phase 权重 ≤ 0（priority < 9 时才检查），则**卸下运行位**（不挂起、不删除），下个相位自然会被重新选中。
3. **运行中保持 + 抢占**：
   - `pickNextGoal` 选出一个挑战者；
   - `shouldPreempt`：**只有 priority ≥ 9（EMERGENCY）才能打断正在跑的 goal**，且 EMERGENCY 可绕过 REPEATABLE 的冷却。非紧急情况一律等当前 goal 完成/失败/连续 BLOCKED 放弃。
   - 旧的"高 3 级就抢"规则被删掉了——那正是"农民种着地突然去造盔甲"的病根。
4. **睡眠守卫**：村民已躺下时，夜间只让 sleep goal 持有控制权（否则导航会让它躺着滑行）；黎明则 `stopSleeping()` 并完成 sleep goal。
5. **运行位交给 goal**：除 farm 外，清空 `scheduledActivity`，避免日程系统跟 goal 抢移动。

### 两段软抽样算法

```
1) 过滤出 active 集合：跳过 completed / suspended / expired / 冷却中 / 离相位的
   （每个跳过的都记下原因，进日志的 skipped=[...]）
2) 若存在 priority ≥ 9 → 直接取最高的那个（EMERGENCY）
3) 否则按 priority 分桶（降序），抽一个「优先级带」，抽中概率 ∝ max(1, priority)
4) 在带内按权重抽一个：
   - REPEATABLE 用 phaseWeight(dayTime)
   - 其它用固定 goal.weight
```

### DECIDE 日志长什么样

`BrainLog.decide`（logger `VillagerBrain`，切换目标时立即打，否则 100 tick 内最多一条）：

```
Mira | DECIDE | phase=DAY | active=[farm(p5,w=6.0), wander(p2,w=1.0),
       craft(p6,w=3.0)] | skipped=[rest#offphase(day), restock#cooldown(18422)]
       | -> farm | band(p6)/weighted(w=3.0)
```

这一条就回答了"我的村民为什么在发呆/为什么不去种地"。

## 8. 执行：BehaviorExecutor + 12 个 Skill

`BehaviorExecutor` 持有一个静态 skill 列表，按注册顺序取**第一个 `canHandle` 返回 true** 的：

| Skill | 处理的目标类型 | 能力门控 |
|---|---|---|
| `SleepSkill` | `rest` / `sleep` | 无 |
| `FarmSkill` | `farm` | FARMING ≥ 1（收获→播种→复耕→开荒，开荒需 FARMING ≥ 2） |
| `SocializeSkill` | `socialize` | SOCIAL（无门槛，聊天本身从 0 级训练 SOCIAL） |
| `GatherSkill` | `gather` | GATHERING ≥ 1 |
| `MoveSkill` / `GotoSkill` / `WanderSkill` | `move` / `goto` / `wander` | 无 |
| `CraftSkill` | `craft` | CRAFTING ≥ 1 |
| `TradeSkill` | `trade` | SOCIAL ≥ 2 |
| `ConverseSkill` | `converse` | — |
| `RestockSkill` | `restock` | —（产出物 = 该职业的起始物品） |
| `AcquireItemSkill` | `acquire_item` | — |

门控表集中在 `BehaviorCatalog`（`farm`/`farm_maintain` FARMING≥1、`farm_reclaim` FARMING≥2、`gather` GATHERING≥1、`craft` CRAFTING≥1、`trade` SOCIAL≥2、`combat` COMBAT≥1；`sleep`/`rest`/`explore`/`move`/`goto`/`wander` 为通用无门控）。

### SkillResult 的含义与后果

| 返回值 | 后果 |
|---|---|
| `SUCCESS` | ONE_SHOT 标记完成并移除；REPEATABLE 撤掉完成标记 + 进冷却 |
| `FAIL` | 先调 `FailureRecoveryPlanner`，再按上一条处理 |
| `DELETE` | 直接移出列表，不补救、不记成功（"删掉这条 todo"） |
| `BLOCKED` | 第 1 次触发 `FailureRecoveryPlanner`；连续 > 5 次放弃（REPEATABLE 加倍冷却，其它标记完成） |
| `RUNNING` | 什么都不做，继续；`runningStreak % 200 == 0` 时打一条 stuck 日志 |

所有被抢占挂起的 goal，在当前 goal 结束时统一 `resumeAllGoals` 恢复。

### 节流细节（一个容易踩的点）

调度器用 `gt - agent.getLastExecutorTick() >= BEHAVIOR_EXECUTOR_INTERVAL_TICKS`（默认 20）判断是否 dispatch。但 `updateAgent` 本身每 `AGENT_THINK_INTERVAL`（默认 100）才跑一次，所以**默认情况下每次"思考"都会 dispatch 一次，skill 的实际 tick 频率 = 5 秒一次，而不是 1 秒一次**。要让它真的 20 tick 跑，得把 `agent_think_interval` 调到 ≤ 20（代价是慢 tick 全部逻辑跟着变密）。

## 9. 失败驱动重规划

技能受阻时把原因写进 `goal.setLastFailure(new Failure(reason, itemId, qty, cap, requiredLevel))`（仅运行时，不落 NBT）。

`FailureReason`：`MISSING_ITEM` / `CAPABILITY_TOO_LOW` / `NO_JOB_SITE` / `NO_RECIPE` / `NO_BED` / `BED_OCCUPIED` / `NOT_NIGHT` / `UNREACHABLE` / `UNKNOWN`。

设计上**"缺工具"和"缺材料"被统一成同一个问题**：都叫 `MISSING_ITEM`，区别只在 `itemId`。恢复三步链（`FailureRecoveryPlanner.recoverMissingItem`）：

1. **找现成的 todo**：扫所有 goal 的 `outcomeItems`，谁的产出含这个物品、且当前真有 skill 能处理 → 优先级 +3（封顶 10）；若是 REPEATABLE 则顶到至少 9（EMERGENCY）以绕过冷却。**这同时就是去重机制**：不新增重复 goal，只是把已有的提前。
   - 例：农民没锄头 → 发现常驻的 `restock` goal 产出含 `iron_hoe` → 把 restock 顶成优先级 9 立刻执行。
2. **能合成就合成**：配方存在 + `SkillCraftCatalog.isUnlockedFor` 通过 → 已有同名 craft goal 就提优先级，否则新建 priority 6 的 craft goal。
3. **否则求购**：在 `VillageSignalBoard` 发 `TRADE_WANT`；若物品有配方但材料不足，对每种缺的材料**递归**执行整条链（深度上限 2，防止 A→B→A）。

能力不够（`CAPABILITY_TOO_LOW`）和其它不可恢复原因只写一条记忆，不做补救。

## 10. LLM 的所有调用点

| 场景 | 位置 | 频率 | 走 LLMGuard？ |
|---|---|---|---|
| 身份（名字+性格） | `VillagerAgentData#generateWithLLM` | 仅新村民 | ❌ 直连 |
| 每日计划 `DailySchedule` | `VillagerSchedulePlanner#generateDailyPlan` | 黎明 1 次/天 | ✅ |
| 傍晚反思 + TODO | `VillagerSchedulePlanner#generateReflection` | 黄昏 1 次/天，且无动作时 | ✅ |
| Harness 结构化决策 | `HarnessDecisionPlanner#decideDailyGoal` | 黎明 1 次/天 | ✅ |
| 内心独白 | `VillagerAgentManager#requestThought` | 冷却 6000 tick，需玩家在旁 | ❌ 直连 |
| 打招呼 | `VillagerAgentManager#tickGreeting` | 每玩家冷却 2400 tick | ✅ |
| 村民间对话 | `VillagerSocialSystem#startConversation` | 每 200 tick 扫描，冷却 6000 tick | ✅ |
| 玩家聊天回复 | `VillagerAgentData#generateChatResponse` | 玩家发一次调一次 | ✅ |
| 交易议价（双方各一次） | `VillagerTradeSystem` | 撮合成功时 | ✅ |
| 建造设计 | `StructureBuilder` | `requestBuild` 时 | ❌ 直连 |
| 记忆压缩 | `VillagerAgentData#summarizeOldMemories` | ≥40 条记忆时 | ❌ 直连 |

### 韧性三件套

- **LLMGuard**：`harness_timeout_ms` 超时看门狗 + 每村民熔断（连续失败 `harness_circuit_failures` 次 → 该村民进入规则-only 模式 `harness_circuit_cooldown_ticks` tick）。
- **失败哨兵**：`LLMService.fail(reason)` 返回带 `\0LLM_FAIL\0` 前缀的字符串，下游必须用 `isFailure()` 判断。这是修"API 挂了 → 村民把报错念给玩家听"的 P0 修复。聊天路径还会再兜一层，失败就回 "Hmm... I seem to have lost my train of thought."
- **DecisionJournal**：每次 LLM 往返都记录 prompt / 原文 / 解析结果 / 校验结果 / outcome，便于复盘。
- 线程安全：回调跑在 LLM 线程池上，**所有对记忆/实体的写操作都要 `serverWorld.getServer().execute(...)` 抛回主线程**（代码里都是这么做的）。

### Prompt 里都塞了什么

以聊天为例（`generateChatResponse`）：名字/职业/性格 → 可合成清单（只列能力已解锁的）+ `TODO:` 协议 → **真实背包清单（ground truth，明确要求不许按职业猜有无）** → 装备/等级/血量/坐标状态块 → 最近 5 条记忆 → 当天对话历史（1 MC 天内的双方交替记录）。

## 11. 记忆 / 能力 / 需求

### 11.1 记忆
`addMemory()` 满 40 条触发异步压缩：把最旧 20 条交给 LLM 压成 2–3 句第一人称，插回列表头部；失败就直接砍多余旧条目。记忆会被塞进几乎所有 prompt（最近 1–8 条）。

### 11.2 长期议程
`LongTermAgenda` 四种：`DebtAgenda`（玩家欠债，可追讨 3 次后扣声望）/ `AcquireItemAgenda` / `DealAgenda` / `GenericAgenda`（泛型兜底，LLM 可以记任意长期事情而不需要写新 Java 类）。由聊天/反思中的 `REMEMBER:` 行创建，支持 `REMEMBER: update <id> ...` 和 `REMEMBER: done <id>`。傍晚反思时会把未完成的 agenda 列给 LLM，让它重新落成 `TODO`。

### 11.3 日程（DailySchedule）
四段（morning/afternoon/evening/night）× 五种活动。解析失败或 LLM 挂了 → 走 `createFallbackPlan`（农民版 / 通用版）。日程不再直接驱动行为，只做两件事：① 把 `scheduledActivity` 交给 `VillagerActivitySystem` 翻成移动；② 作为 prompt 上下文。

### 11.4 能力池
- 出生：全部 0 级，随机一个"爱好"1 级（按 villagerId 确定性）；认领职业时主能力补到基线 **3** 级（`healProfessionCapability`，幂等、只升不降，顺便给旧存档做迁移）。
- 成长：练习/击杀 `CAPABILITY_PRACTICE_XP`、聊天拜师 `CAPABILITY_CHAT_XP`（村民间对话时双向传承对方主能力）。
- 锈蚀：2 天宽限期后，按 `1 - (d/14)²` 的平方曲线衰减，掉到 0 就移除（对应等级门控的东西随之重新上锁）。每天只 decay 一次，日期落 NBT 防重复。
- 作用：门控 skill（`passesCapabilityGate`）、门控配方（`SkillCraftCatalog.isUnlockedFor`）、放大规划权重（×(1+0.3×level)）、镜像原版交易等级（`(level-1)/2`，封顶 5）。

### 11.5 需求与心情
饥饿每 1200 tick −5，< 40 自动吃（恢复 = 营养值 × 8），< 10 且没吃的就写一条抱怨记忆。夜间每 1200 tick 疲劳 +4，白天 −2。心情 = 饥饿 + 疲劳 + 平均关系分的加权分 → HAPPY / CONTENT / NEUTRAL / ANXIOUS / DISTRESSED，注入所有 prompt。

## 12. 三条不走目标队列的旁路

### 12.1 战斗 / 逃跑 / 集结
`performCombatActions` 在**村民完全空闲**（`currentAction == null`）时才扫威胁，避免打断耕地/合成。

- 打得过（`wouldWinSolo` 且 `mayAttack`）→ `ATTACK`：暂停运行中的 goal（`suspendRunningGoal`）、挑最好的武器、0.4 速度追击、进入攻击距离按 cooldown 输出、目标死了给 COMBAT 练习 XP、脱离后恢复被暂停的 goal。
- 打不过 → 在 `VillageSignalBoard` 上登记一次 `respond`（贡献自己的 `combatPower`）→ 若全场合力 ≥ `combat_charge_total_power` 就**转头一起冲**，否则边跑边喊（保持安全距离而非无限跑，喊 30 次扫描没人来就放弃）。
- 没威胁但听到 20 格内有集结 → 跑过去支援。
- 裸手村民贡献 0 战力，所以一群拳头永远触发不了冲锋。

### 12.2 建筑
`BuildJob` 由 `BuildOrderPlanner` 拆成逐块的 PLACE/BREAK 步骤，每 `BUILD_BLOCK_INTERVAL` tick 推进一步；只有在当前动作属于 PLACE/BREAK/BUILD 时才占用村民。

### 12.3 睡眠（特殊待遇）
睡觉期间 `SleepSkill` 会**整晚返回 RUNNING** 不释放运行位，这正是修"躺着滑行"的关键（任何别的 goal 都拿不到下发导航的机会）。每 tick 的 `wakeAtDawn` 在黎明把它叫起来；睡着时按夜间长度回血约 25% 最大生命。

## 15. 当前缺口 / 值得注意的不一致

1. **skill 真实 tick 频率被 think_interval 卡住**（见 §8）：默认配置下 skill 每 5 秒才跑一次，导航、卡死检测（GOAL_STUCK_TIMEOUT=200）之类的节流计数也因此被拉长。
2. **`requestThought` / 记忆压缩 / 身份生成 / 建造设计绕过 `LLMGuard`**：没有超时看门狗和熔断保护，理论上卡住会一直占着 4 线程的池子。
3. **傍晚反思是 agenda→goal 的唯一主动桥接点**：债务/求购这类长期承诺只有每天黄昏那一次机会转成 todo，平时完全被动（goal 失败时也只有 MISSING_ITEM 类会触发补救）。
4. **`scheduledActivity` 仍然是一条并行的行为来源**：`VillagerActivitySystem` 会把 crafting/exploring/resting 翻成真实导航；goal 一旦占用运行位会清空它（farm 除外），但"日程"和"目标"两套语义仍共存，`docs/架构反思与精简方案.md` 里提出过统一目标漏斗的方向。
5. **`VillagerAction` 的相位模型偏粗**（SEARCHING/WALKING/ACTING/WAITING）：多步 skill（开荒、建造）必须把状态挂在 agent 上（`FarmReclaimState`、`BuildJob`），因为 skill 本身是单例。
6. **回家睡觉仍部分依赖原版 `HOME` POI**：`SleepSkill` 已能用 `WorldStructureIndex` 找床兜底，但结构索引与消费侧尚未完全打通。
7. `parseGoalDirectives` 的合法类型集合（craft/trade/socialize/build/move/converse/goto）与实际能跑的 skill 集合不完全对齐（例如 `build` 没有对应 skill），这类 goal 会一直停在"没有 skill 认领"的状态直到被每日剪枝清掉。
