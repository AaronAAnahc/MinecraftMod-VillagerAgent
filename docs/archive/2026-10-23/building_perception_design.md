# VillagerAgent：让 AI 理解方块建筑结构的方案（调研 + 设计）

> 目标：让村民（AI）能够理解一栋房子的**各个部件**——柱子、墙、门、窗、屋顶、地板、以及房间范围。  
> 约束（用户明确）：**不引入额外的神经网络 / 模型**。村民侧只有 **LLM** 和 **VLM**；截图式 VLM 不作为主路径。  
> 结论先行：建筑结构的"感知 / 检测"全部用**确定性几何算法**（CPU 上跑，无需 GPU、无需训练）在 Java/模组侧完成，把结果整理成**结构化文本/JSON** 喂给 LLM 理解。这正是本方案能契合约束的关键——下面所有"检测"步骤都不是神经网络。

---

## 0. 关于《Describing Minecraft Worlds》博客（nicolasgatien.com，2026-02-02）

这篇博客是**分层文本摘要**思路的早期实践，和我们的目标强相关但**互补**：它解决"远处世界怎么描述"，而我们解决"近处建筑怎么拆解"。

**博客做法：**

1. 取 agent 周围 **65 格半径内**的所有方块列表。
2. 遍历每个方块，用 **skyLight（天空光照等级）** 判断它是否接近地表——只关注"满天空光"的方块，因为这决定了**世界的轮廓（contour）**。洞穴暂时没解决。
3. 按**生物群系（biome）**&#x805A;合：外层每个方块按所属 biome 累加，每个 biome 取所有地表方块位置的**平均坐标**作为其位置。
4. 生成一段极简文本，例如：
   ```
   The following biomes are around you: plains, stony_shore, meadow,
   The plains is to the South and is located at: -989 78 2520. It makes up 96% of your surroundings.
   The stony_shore is to the West and is located at: -1054 72 2452. It makes up 4% of your surroundings.
   The meadow is to the South and is located at: -995 91 2592. It makes up 0% of your surroundings.
   ```

5. 作者自己列出的**局限**（原文）：
   - 无法检测结构（structures）
   - 无法检测洞穴（caves）
   - 无区域内实体的描述
   - 无法检测**玩家建造的结构**
   - 不知道单个方块的位置

**对我们的启示：**

- 它的"近场精确 + 远场 biome 摘要"是很好的**感知层外层**写法，可直接复用为 VillagerAgent 的"远景描述"。
- 但作者明确承认它**完全不能理解建筑**——这正是我们要补的那一块。我们的方案在它之上叠加一个"近场确定性结构解析"模块，专门产出柱子/墙/门窗/屋顶/房间。
- 它最后一句"maybe a 5x5 grid around the player + broad description"也印证了"近场精、远场粗"的分层原则。

## 1. 问题定义与约束推导

### 1.1 目标

让 LLM 真正"理解"一栋房子：哪里是柱子、哪里是墙、哪里是门/窗、哪里是屋顶、房间范围多大、门朝哪。

### 1.2 约束

- 村民侧只有 **LLM**（负责理解/推理/对话/记忆）和 **VLM**（可选兜底，**不依赖截图**）。
- **不引入额外神经网络/模型**（不跑 3D U-Net、不跑 Grounded-SAM、不训 detector）。

### 1.3 约束推导出的关键结论

"让 AI 理解建筑" ≠ "用 AI 去识别建筑"。识别/检测这一步必须**前置到模组侧**，用经典几何算法完成：

- 占据栅格、连通分量（flood fill / union-find）、形态学膨胀/腐蚀、**RANSAC 平面拟合**、**PCA 主方向**、连通性测试——这些都是**确定性算法，不是神经网络**，CPU 上跑、可复现、免费。
- 模组的产物是一份**结构化描述（文本/JSON）**，LLM 只是"读这份描述并理解、推理、对话"。
- 这样 LLM 看到的是"北边那栋朝南木屋、分两间、东墙有窗、门口连院子"，而不是几百个坐标——信噪比和 token 成本都最优。

## 2. 核心范式：判别"空间"而非"方块"

### 2.1 为什么给方块写规则是死路

用户列出的反例，每一条都在说明：**把"一坨连通方块"当判别对象、再用形状/材质规则贴标签，这个抽象本身错了**。

| 反例                    | 形状/材质规则为什么失败    |
| --------------------- | --------------- |
| 柱子可以是 1×1 / 2×1 / 2×2 | 写不全所有足迹组合       |
| 墙可以有厚度                | 厚墙判不成"薄墙"       |
| 门不接地                  | "接地"判据崩         |
| 墙上洞 A 是门、洞 B 是窗       | 没有门方块就没法分       |
| 墙外挂装饰方块               | 装饰被算进墙          |
| 墙贴着山体、材质 = 石头         | 石墙和山分不清         |
| N×1×N 结构往外伸一堆块        | 规则说不清"伸多少就不是墙"  |
| 阁楼屋顶用阶梯方块，像斜墙         | 屋顶和墙难分（详见 §4.8） |

### 2.2 关系型定义（通用、与形状/材质解耦）

所有结构元素都从 **自由空间（可走体积）与其边界、连通关系** 推导，不看方块形状/材质：

| 元素               | 关系型定义                               |
| ---------------- | ----------------------------------- |
| **房间**           | 自由空间经"门洞闭合"后的**连通分量**               |
| **墙**            | 自由空间与实心的**侧边界面**（边界方块，自由空间在它的左右）    |
| **地板 / 屋顶（天花板）** | 边界方块，自由空间分别在其**上 / 下**              |
| **柱**            | 四周（≥3 面）被自由空间包围的**竖直实心体**           |
| **门**            | 墙平面上的缺口，且**穿过它能连通两个自由区域**           |
| **窗**            | 墙平面上的缺口，但**不形成通道**（悬空 / 对外 / 不连通两侧） |
| **房间分隔线**        | 两间房自由空间之间的那排墙界面                     |

这套定义一次性消解 §2.1 的全部反例。

## 3. 参考与现成方法

### 3.1 Numen（言出法随）的自我中心语义网格

- 生成"语义字符网格"的工具是 **`look_around`**（`LookAroundTool.java`），不是 `inspect_block_storage`（后者只是读方块内部物品/流体/能量的探针）。
- `look_around` 产出的是**移动可达性地图**（`.` 平地 / `#` 墙 / `^` 可跳上 / `~` 水 / `!` 岩浆 / `x` 危险缓冲 …），它**丢掉方块类型**，只回答"我能不能走到这格"——**认不出树、房子、房间**。
- `classify()` 复用了寻路模块 `MovementHelper` 的确定性规则（`canStandAt` / `fullyPassable` / `isLava`），竖直维度坍缩成 `delta` 符号。
- **结论**：`look_around` 是"地形层"，不是"结构层"。我们要的是"结构层"，需要另外补。

### 3.2 精确检测的四种路线（我们选 ②）

| 派别                 | 精确性       | 成本        | 是否需额外模型     | 适配度                      |
| ------------------ | --------- | --------- | ----------- | ------------------------ |
| ① 游戏原生 BoundingBox | 100%      | 免费 CPU    | 否           | 只认"登记过"的结构（村庄/要塞/你存过模板的） |
| **② 确定性体素分割**      | 100%      | CPU       | **否（经典算法）** | ⭐ 主选，对任意自建/自然物           |
| ③ 3D 深度学习          | ~98% mIoU | GPU + 训练  | 是           | 偏重，违约束                   |
| ④ 视觉 2D 分割         | 像素级（2D）   | GPU + VLM | 是（VLM）      | 用户不偏好                    |

### 3.3 非连续结构分组（piece-first + 关系合并）

纯连通分量只能吐"连在一起的一坨"，会遇到过分割（一栋房子被切成墙/地板/烟囱）和欠分割（两栋贴着的楼合并）。解法（均无需 NN）：

- **Minecraft 自身 StructurePiece 模型**：每个结构 = 多个带独立 `BoundingBox` + 朝向 + 连接器的 `Piece` 组成，天然允许不连续。映射到村民：每盖一栋楼 = 一个 piece，一片农庄用"邻近度 + 连接器（小路/栅栏/门洞）"归到一个 structure id。
- **Hydra（MIT, arXiv:2201.13360）**：把"网格→物体→场所→房间→建筑"做成 3D 场景图层级；用**膨胀空闲空间使门洞闭合 → 自由空间裂成房间**。
- **KDE 关系特征阈值**（ScienceDirect 2025 建筑点云解析）：对每对片算 4 个几何特征（体积极比 / 垂直间距 / 中心距 / XY 投影重叠），用核密度估计找自然断点分组，不要求接触。
- **视觉分组免训练**：OpenVoxel（arXiv:2601.09575）多视图 2D SAM 掩码按 IoU 跨视图匹配合并——但依赖 VLM，非主路径。

### 3.4 建筑几何 / 场景图领域现成方法（都核实过）

- **Hydra (MIT, arXiv:2201.13360)** — 自由空间膨胀闭合门洞 → 房间；3D 场景图层级。理论支柱。
- **CMU Xiong et al. 2013 (Automation in Construction)** — 体素化点云抽平面片 + CRF 上下文标注（墙/地/顶）+ 可见性推理找开口。经典通用法。
- **Image-to-BIM (MDPI Buildings 2026)** — RANSAC 抽墙平面、PCA 取墙方向/范围、DBSCAN 聚类门窗；明确 **门=接地 / 窗=悬空**；输出 `walls/windows/doors` JSON。格式几乎就是我们要的。
- **Cloud2BIM (arXiv:2503.11498)** — 墙轴法：墙中线求交 → 闭合多边形 → 房间（根本不搜空空间）；密度法找开口。开源可借鉴。
- **Scan-to-EDTs (MDPI Buildings 15(22):4060)** — 本体 `D = U+F+C+W+L+O`（未分类/地/顶/墙/柱/开口），柱用俯视 YOLO 检（我们改用 §4.6 的关系定义即可，无需 YOLO）。
- **IJGI 2017, 7070250** — 专门讲门/窗形态学模式分类（"reach the floor = door, else window"），直接回应"洞 A/B 怎么分"。

## 4. 给 VillagerAgent 的关系型结构解析管线（核心，纯确定性、无 NN）

> 输入：村民周围某区域（如半径 16–24 格，高度覆盖地面±若干层）。  
> 输出：结构清单（见 §6），直接并入村民记忆 / 喂给 LLM 对话。

### 4.1 体素化 → 占据栅格

把区域读进 3D 布尔栅格（每格 1 方块，记录"实心 / 空 / 可站立"）。MC 里你本来就握有方块世界，这步几乎零成本。

### 4.2 2.5D 柱列表示 `[floorY, ceilY]`

导航是 2D（地板平、人不飞），但房间是 3D。**每根 (x,z) 列记录它空的可站立区间 [floorY, ceilY]**（地板高度、天花板高度）。这样既保留 2D 导航效率，又补回垂直信息——这是区分"往上到底是墙还是屋顶"的基础。

**柱列是逐列记录的，天然不假设房间是立方体**：房间的真实形状由"哪些 (x,z) 列属于它" + 每列高度区间共同决定（见 §4.3），L 形、错层、带洞的房间都能如实表达。

### 4.3 自由空间 / 房间（膨胀闭合门洞）

- 自由空间 = 空且能站（有头顶净空）的格子集合。
- **房间 = 自由空间经"门洞闭合"后的连通分量**：对占据栅格做形态学**膨胀（dilate）**，门口这种窄开口被"堵死"，自由空间自然裂成几块 = 房间。完全不依赖墙的几何。
- **房间是任意形状的体素集合，不是立方体**。算法只产出"哪些 (x,z,y) 体素属于哪个房间"，从不假设盒子形状。L 形、带中柱、错层、拱顶全部照常处理（边界判定是逐体素局部的，见 §4.4）。
- **房间范围表示（关键，回应"自由体积不一定是立方体"）**：不要用单一包围盒表达房间，而用忠实且省 token 的描述——
  - `footprint`：**2D 栅格掩码**（小字符网格，R=房间 / 空格=非房间），形状 1:1 还原，token 成本与 look_around 同级；
  - `height`：每根 (x,z) 列的 [floorY, ceilY]（规则房间可只给一组，错层/中柱处单独标注例外）；
  - `bbox`：**仅作粗筛/概览提示**（"大致在这片区域"），不用于几何计算，避免框进墙体与外部空间。

### 4.4 墙 / 天花板 / 地板 = 房间自由体积**边界**方块到自由空间的**方向**

**关键修正：不要逐块扫描"实心块 + 上方有空"来定地板**——否则地板上凸起一个方块（其上方也有自由空间）会被误判为地板，但它显然不是；同理从天花板垂下的方块会被误判为天花板。

正确做法：**先有房间自由体积（§4.3），再取其边界**。地板 / 天花板 / 墙是**该自由体积的 6 个边界面所对应的实心方块**：

- 自由体积**底面**之下的实心块 → **地板 Floor**（房间自由空间所"坐"的表面）
- 自由体积**顶面**之上的实心块 → **天花板 / 屋顶 Roof**
- 自由体积**侧面**邻接的实心块 → **墙 Wall**

**这样，任何位于自由体积"内部"的实心体（凸起块、悬挂块、柱基、家具）都不是任何边界 → 永远不会被标成地板 / 墙 / 顶**，而是归为「房间内障碍物 / 物体」，可进一步按形态细分（1 格高→台阶/凸起；竖直叠堆→基座/柱；顶上可走→平台）。

辅助判定（与 §4.6 柱/物体规则一致）：一个实心块若**四周（≥3 个水平方向）邻接同一房间的自由空间**，说明它是房间内的「孤岛」→ 判为**物体/障碍**，而非地板/墙。这兜住了 1×1 凸起块。

方向判断（侧/下/上）仍用于给边界面定具体角色；轴对齐建筑基本零歧义，斜屋顶用局部法线主方向（PCA）兜底。

### 4.5 开口（门 vs 窗）= 缺口 + 连通性测试 ⭐ 回应"没门方块怎么分洞 A/B"

1. 把墙面投影到 2D 二值图（实心=1 / 缺口=0）→ 形态学找**洞（缺口）**。
2. 对每个洞做"**穿过它能否连通两个自由区域**"测试：
   - 能连通两侧（房间↔房间 / 房间↔室外）→ **门**
   - 不能（悬空、对外、不形成通道）→ **窗**
3. 即使你**不放门方块**，只要墙上有个缺口头顶连通两侧，就判为门——比依赖一个门方块稳健且通用得多。这直接回答了用户的"我墙上的洞 A 是门、洞 B 是窗，没有门方块怎么办"。

### 4.6 柱 = 四周被自由空间包围的竖直实体

- 判定：**竖直实心体**，且在其四周（≥3 个水平方向）邻接自由空间，上方还承着天花板/物体。
- **足迹大小无所谓**（1×1 / 2×1 / 2×2 都算柱），看的是"被包围"而非形状。

### 4.7 房间范围 / 分隔线

- 房间范围 = §4.3 连通分量的 (x,z) 投影 + 高度区间。
- 分隔线 = 两间房自由空间之间的那排墙界面（即 §4.4 的墙，按所属房间归属即可）。

### 4.8 屋顶 vs 墙（回应阁楼反例）⭐

用户反例：顶楼地板 + 周围 2 格高竖直围合 + 上面用楼梯方块拼阶梯状屋顶，阁楼可走——会不会把屋顶误判成墙？

- 那 2 格高竖直围合：内侧面邻接自由空间在**侧边** → 判为**墙**。✓
- 上面阶梯状屋顶：每块实心方块是**从下方**邻接阁楼自由空间（阁楼在它底下）→ 判为**屋顶/天花板**。✓
- 一道斜屋顶边缘会**自然裂成"墙段 + 顶段"**，不会整片误判成墙。
- 两层楼之间的楼板：上接二楼、下接一楼 → 同时是"二楼地板"和"一楼顶"，关系型定义天然支持双标签。

### 4.9 非连续分组：片 → 结构（piece-first + 关系合并）⭐ 回应"结构不一定连续"

1. **分片（Piece）**：连通分量 flood fill → 得到一堆 piece（允许碎，烟囱/墙/地板各自独立没问题）。
2. **合并（Structure）**：建一张 piece 关系图，边由三类信号决定——
   - **连接器**：两 piece 间有路径/栅栏/门洞/桥 → 同结构；
   - **空间关系阈值**：中心距 + XY 投影重叠 + 垂直间距落在 KDE 自然区间内 → 同结构；
   - **外壳/房间**：可选，检测围合空闲空间把多个房间归一栋。  
     跑一遍社区发现（或直接阈值并查集）→ 每个连通社区 = 一个结构。
3. **生成期真值（最高杠杆）**：因为结构是你村民**自己盖的**，盖的时候你就知道每块的归属——放置时直接把每个 piece 的 bbox + structure id 存下来（即 MC `StructureStart/Children` 做法），**100% 精确、零检测成本**；只有自然生成 / 玩家盖的东西才在扫描时跑上面的分组。

| 阁楼阶梯屋顶误判为墙         | §4.8 按局部邻接方向裂成"墙段+顶段"                  |
| 房子带独立烟囱 / 多栋不连续    | §4.9 piece-first + 关系合并                |
| 地板凸起一块（其上也自由空间）误判为地板 | §4.4 地板=房间自由体积**底面边界**；体块在自由体积**内部**→永不成为边界→归为障碍物；辅助：四周≥3面邻自由空间=孤岛→物体 |

## 7. 系统架构（分层，符合约束）

```
┌─ 感知层（Java/模组侧，确定性算法，无 NN）──────────────┐
│ • 体素化 + 2.5D 柱列 [floorY, ceilY]                  │
│ • 自由空间 / 房间（膨胀闭合）                           │
│ • 墙/顶/地（边界方向） + 开口(门/窗, 连通性) + 柱      │
│ • 非连续分组（piece-first + 关系合并）                 │
│ • 远景：biome 分层摘要（借鉴 Describing Minecraft…）   │
│ • 自建房屋：生成期语义真值（100% 精确、零成本）        │
└───────────────────────────┬──────────────────────────┘
                            ▼ 结构化文本/JSON
┌─ 表征层 ─────────────────────────────────────────────┐
│ 结构清单（§6 格式）→ 并入村民长期记忆 / 即时上下文      │
└───────────────────────────┬──────────────────────────┘
                            ▼
┌─ 理解层：LLM ────────────────────────────────────────┐
│ 理解部件、推理导航/社交/对话、更新记忆、规划           │
└───────────────────────────┬──────────────────────────┘
                            ▼ （可选、不依赖）
                   VLM 兜底：仅当确定性算法遇到歧义且非截图关键时
```

- **VLM 的角色**：用户不偏好截图 VLM，故仅作为**可选兜底**——当确定性几何算法遇到极少数歧义（如极端非轴对齐、装饰与主体严重纠缠）且影响理解时，才考虑送一帧给 VLM 澄清。**主路径完全不依赖 VLM。**
- **知识层（可选）**：内嵌一份轻量配方/依赖 KG（谁挖谁、合成树、工具门槛），只给实体名就够 LLM 理解依赖，防幻觉。这部分也可纯 JSON 维护，无需模型。

## 10. 已知问题与开放问题（自检 / 用户压力测试）

> 以下为把"先检测可行方块 → 2D 切片 → 套边界规则"管线当作真算法检验时暴露的问题。均需在实现前解决。

- **P1 缺"室内/室外"判别（前提缺失）**：自由空间含整个室外，不先区分包围/开放，房间/地板/墙推导全建立在错误的自由体积上。→ 加**围合度测试**：自由体积对外开口比（开口面积/总表面积）低于阈值且四周被实心包围 → 室内房间；否则室外。或优先用生成期真值标记建筑外壳。
- **P2 2D 切片丢失竖向结构**：竖向竖井、错层（不同高度足迹不同）、上下层错位房间，压成 (x,z) 足迹会丢信息。→ 房间用 `(x,z,y)` 体素集合，必要时按高度分层给足迹。
- **P3 单区间 `[floorY,ceilY]` 无法表达错层**：一根列里"地板—凸起平台—上层"有两个自由区间。→ 柱列每列存**自由区间列表** `[(y0,y1),(y2,y3),...]`，平台/夹层作为中间区间。
- **P4 门/窗规则误判**：内部窗（连通两房间）、朝室外的窗（室外也是自由空间）都会被"连通两自由区域=门"误判为门；高处封死缝也误判门。→ 区分"室外"与"另一房间"；门=连通室内↔室外或室内↔室内且位于**通行高度**（地板起约 1–2 格）；窗=连通但位于高处/非通行高度。靠"开口通行高度"而非仅连通性。
- **P5 非完整方块破坏二值占据**：半砖/楼梯/栅栏/玻璃板/活板门/门本身不是完整方块，方向规则假设实心/空二值会失真。→ 占据栅格改用"**是否阻挡移动 / 是否构成可站立表面**"而非"视觉实心"；半砖/楼梯顶视作地板表面、底视作天花板；栅栏/墙类记"阻挡但通透"。
- **P6 拓扑分不出"结构柱"与"家具/树"**：四周被自由空间包围的竖直实体，可能是柱、衣柜、树干、装饰——拓扑相同。纯拓扑只给"孤立竖直实体"，无法判是否承重柱。→ 结构元素语义靠**生成期真值**（建造时标记此块为柱）或材料/上下文（柱通常连屋顶+地板、材质与墙一致）；纯拓扑产物交 LLM+记忆+生成真值进一步判定。
- **P7 柱规则对贴墙/角柱失效**：墙角柱、半嵌入柱自由面<3 → 误判成墙。→ 柱定义看**竖向连续性 + 上下承重关系**（顶接屋顶、底接地板）比自由面数更关键；贴墙柱按"突出于墙面的竖直体"判定。
- **P8 膨胀阈值任意**：宽开口（双开门/拱门）超膨胀量 → 两房间合并；窄壁龛被封 → 误拆房间。→ 膨胀量按标准门宽设定，并对宽缺口做**开口宽度识别**（宽度超阈值视为开放连通、不闭合）；结合生成期真值避免。

**核心结论**：该管线在"未先解决什么是室内、什么是完整方块、什么是结构语义"的前提下，过早把拓扑当成了全部答案。上述 P1/P5/P6 是必须在感知层前置解决的前提，P2–P4/P7/P8 是规则层的边界修正。
