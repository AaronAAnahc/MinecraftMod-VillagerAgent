# VillagerAgent × 游戏 AI Agent 岗位能力对齐与可落地技能规划

> 调研依据：网易伏羲 / 雷火 / 互娱 AI Agent 岗位 JD（2026-08 在招）+ 行业游戏 AI 实践（talently、Sperasoft、网易伏羲技术文、LinkedIn "How to Create Agents"、CGDC 吕唐杰演讲等）。

---

## 一、游戏 AI Agent 岗位核心关注的能力维度

### 1. 感知与认知（Perception & Cognition）
- 视觉锥（带遮挡 / 距离 / 光照）、听觉半径、记忆衰减（最后已知位置）、共享感知（感知广播）。
- 网易伏羲在《永劫无间》Copilot 中把"感知 → 理解 → 执行"做成完整链路；行业共识是"感知决定手感，先把感知做扎实"。
- **VillagerAgent 现状**：已具备 Far / Mid / Near 分层感知底座，是天然切入点。

### 2. 决策与规划（Decision & Planning）
- 行为树（BT）+ 黑板（Blackboard）已是 AAA 战斗 / 复杂 NPC 主流；FSM 用于简单敌人；Utility AI 用于模拟类；GOAP / HTN 用于长程目标规划。
- 网易雷火 JD 明确要"多步规划能力""规划 / 记忆 / 工具调用"。
- **VillagerAgent 现状**：目前是 LLM 自由决策，缺结构化决策层。补一层 BT / Utility 既能对齐 JD，又能让 LLM 只负责高层目标，降低幻觉与不稳定性。

### 3. 导航与运动（Navigation & Locomotion）
- A* / NavMesh / 流场；局部转向（RVO 避障）；动态重规划；"门道问题"（多智能体在窄道争用）。
- 网易伏羲用 RL 把复杂地形寻路成功率从 77% 提升到 99%。
- **VillagerAgent 现状**：已知"回家睡觉"仍走原版 HOME POI，未接回 WorldStructureIndex——这是最能体现"你理解并修复真实架构断层"的切入点。

### 4. 群体与多智能体（Multi-agent & Emergence）
- 角色分配（主攻 / 侧翼 / 支援 / 警报）、环形战斗、集群算法（分离 / 对齐 / 聚合）、警报传播。
- 网易强调"可控涌现""NPC→NPC 网状交互""AI-Native 分层（底层 Agent + 上层事件触发）"。
- **VillagerAgent 现状**：村庄天然是多智能体场景，最适合做"警报 / 疏散 / 分工"的涌现演示。

### 5. 记忆与人格（Memory & Persona）
- 长期记忆、关系图谱、角色随互动"成长 / 演变"；避免人格漂移需"人格锚定"。
- 网易《逆水寒》智能 NPC：LLM 内容生产 + 人设对话 + 多模态互动 + 长期关系。
- **VillagerAgent 现状**：可用 WorldSavedData 持久化"村民 ↔ 玩家"互动史，做关系图谱与长期记忆。

### 6. 机器学习与自适应（ML & Adaptation）
- 强化学习（PPO 等）、模仿学习、自适应难度、玩家行为预测。
- 网易有专职"强化学习 / 模仿学习方向"岗（AI Bot 投放、难度调整、训练部署平台）；雷火要"智能博弈 / 自博弈"。
- **VillagerAgent 现状**：纯 Forge mod 跑不了真 RL 训练（需 Python / PyTorch 外部训练）。但可把村庄做成**评估 / 沙盒环境**（暴露状态-动作-奖励接口），作为 RL 叙事的强支撑；轻量"规则自适应"可 in-mod 实现。

### 7. 对话与多模态（Dialogue & Multimodal）
- LLM 自由文本对话、情感模型、动态叙事；语音 / 表情 / 动作多模态联动。
- 网易《逆水寒》《永劫无间》均已落地 LLM 对话 + 语音 + 表情。
- **VillagerAgent 现状**：LLM 已接入，可加"玩家聊天 → 村民带人格回应 + 记忆"，做成智能 NPC 演示。

### 8. 性能与工程（Performance & Engineering）
- 帧预算（1–16ms / 帧）、空间分区、AI LOD、分帧更新、tick 预算管理、行为线程。
- **VillagerAgent 现状**：已用事件驱动 + 持久化规避周期扫描，可再加 AI LOD / 距离分级 tick。

### 9. 调试与可视化（Debug & Visualization）
- Visual Logger、自定义调试绘制（感知锥、警觉度条、黑板状态）。
- **VillagerAgent 现状**：已有 config-driven overlay，可升级为"感知锥 / 警觉度 / 黑板"可视化。

### 10. 工具链与数据驱动（Tooling & Data-driven）
- 设计师可编辑行为、黑板、EQS；数据驱动授权。
- **VillagerAgent 现状**：可把 BT / Utility 参数与 LLM prompt 做成配置文件（呼应已有的 config 习惯）。

## 二、可在 VillagerAgent 中落地的技能清单（按岗位说服力排序）

> 可行性：高 = 纯 Java / Forge 可完成；中 = 需一定设计但可行；低 = 需外部训练 / 大量工程。

| # | 技能 | 对应能力维度 | 在项目中如何实现 | 可行性 | 岗位说服力 |
|---|------|------|------|------|------|
| 1 | **行为树 + 黑板** | 决策与规划 | 用 Java 实现 Selector / Sequence / Decorator / Condition 节点 + Blackboard 共享数据；BT 负责"工作 / 睡觉 / 逃跑 / 社交"等中低层行为，LLM 退居高层目标生成 | 高 | 每个游戏 AI JD 都点名行为树 / 黑板，最对口 |
| 2 | **感知升级（视觉锥 + 遮挡 + 听觉 + 记忆衰减 + 共享感知）** | 感知与认知 | Near 层加视野角 + 距离 + 射线遮挡；监听方块破坏 / 生物声响做听觉；用衰减记忆存"最后已知威胁位置"；邻居村民间广播感知 | 高 | 直接命中感知链路，且已有分层感知底座 |
| 3 | **长期记忆 + 关系图谱** | 记忆与人格 | WorldSavedData 持久化"村民 ↔ 玩家"互动史（好感 / 敌意 / 事件），驱动人格与后续行为 | 高 | 命中《逆水寒》智能 NPC"长期记忆 / 关系"要求 |
| 4 | **LLM 工具调用（Function-calling）** | 决策与规划 / 工具链 | 给村民 LLM 定义工具集（go_to_bed / alert_others / give_item / flee），以函数调用触发 in-game 动作，而非自由文本 | 中 | 命中雷火"工具调用"硬要求，体现 Agent 工程化 |
| 5 | **群体 AI / 角色分配 / 警报传播** | 群体与多智能体 | 威胁下村民按角色（警报者 / 疏散者 / 守护者）分工；威胁感知广播触发群体疏散 / 集结 | 高 | 命中"可控涌现 / NPC→NPC"，多智能体最强演示 |
| 6 | **导航回填：WorldStructureIndex 接回回家寻路** | 导航与运动 | 用建筑索引替代原版 HOME POI，让"回家睡觉"走结构感知路径；环境变化时动态重规划 | 中 | 展示你发现并修复"消费断层"的真实工程能力 |
| 7 | **调试可视化增强（感知锥 / 警觉度 / 黑板）** | 调试与可视化 | 在现有 config overlay 上升级绘制视野锥、警觉度条、黑板键值 | 高 | 命中 Visual Logger 要求，演示 / 排错双杀 |
| 8 | **AI LOD / 分帧更新 / tick 预算** | 性能与工程 | 按与玩家距离分级 tick 频率；远村民低频更新 | 高 | 命中"帧预算 / AI LOD"，呼应已有的事件驱动优化 |
| 9 | **规则自适应（谨慎度随玩家行为调节）** | 机器学习与自适应 | 村民对玩家的谨慎 / 敌意随"被攻击次数"等上升，影响逃跑阈值与交互意愿 | 高 | 轻量版"自适应难度"，不依赖外部训练即体现 ML 思想 |
| 10 | **NPC 对话人设（聊天 → LLM → 带人格回应）** | 对话与多模态 | 玩家聊天输入 → LLM（带人设 + 记忆）→ 村民文本 / 动作回应 | 中 | 直接命中"智能 NPC"岗，演示效果拉满 |
| 11 | **GOAP / HTN 长程规划** | 决策与规划 | 给村民定义目标（如"备粮"）与可行动作，运行时搜索动作序列 | 中 | 命中"多步规划"，复杂度高，作为进阶项 |
| 12 | **RL 沙盒化（村庄作为训练 / 评测环境）** | 机器学习与自适应 | 暴露 (state, action, reward) 接口 + Gym-like wrapper，外部用 SB3 训练村民策略 | 低 | 对 RL 方向岗是强叙事：把 mod 讲成"可训练环境" |

## 三、落地建议（给面试官的讲故事主线）

**主线串法**：「我做了一个 LLM 驱动的村民智能体，完整覆盖了 SENSE → THINK → ACT 闭环，并对照工业级游戏 AI 逐项补齐了感知 / 决策 / 记忆 / 群体 / 可视化。」

- **必做（高可行性、高对口）**：#1、#2、#3、#5、#7、#8 —— 纯 Forge 就能完成，每一项都能对应到 JD 里的一个关键词。
- **进阶（中可行性、强差异化）**：#4、#6、#9、#10、#11 —— 体现 Agent 工程化与"修复真实断层"。
- **叙事（RL 方向岗）**：#12 —— 不必真训，但能把项目升维成"可控可评测的智能体环境"，正好对接网易雷火"Agent 训练脚手架 / 强化学习"方向。

> 注：纯 Forge mod 难以承载真·强化学习训练（缺 Python / PyTorch 训练闭环）。若投的是"强化学习 / 模仿学习"硬方向岗，建议另起一个小型 RL 项目（如用 Stable-Baselines3 在自定义 Gym 环境训一个 Bot），与 VillagerAgent 形成「架构演示 + 算法落地」组合拳。
