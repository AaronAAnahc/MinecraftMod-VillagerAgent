# VillagerAgent — 自主意识涌现模块分析

> 基于 2026-04-23 版本源码的完整调查，分析当前项目已实现能力与实现"自主生活与意识涌现"所需的缺失模块。

> - **建筑感知（原 P0 3.3「零代码」）**：已实现 `BuildingLocator`（床→房间，距离场+同步双类别分水岭）+ `WorldStructureIndex`（事件驱动、持久化、跨重启）。详见 `building_detection_implementation.md` / `bed_room_search_implementation.md`。
> - **建造系统（原「未实现 5%」）**：已实现放置/破坏/大规模建造（`BlockInteractionAction`/`BuildOrderPlanner`/`StructureBuilder`/`BuildJob`）。详见 `world_interaction_design.md` 的「实现状态」。
> - **LLM 行动决策器（原 P0 3.1「纯随机生成目标」）**：已新增 `ai/harness/` 包（`LLMGuard`/`DecisionJournal`/`DecisionSchema`/`ActionValidator`/`HarnessDecisionPlanner`，受 `harness_drive_daily_goal` 门控，默认关）+ `processGoals` 统一派发（craft/gather/move/converse/trade/socialize）。
> - **职业合成（原「5 配方」）**：已落地 `ProfessionCraftCatalog` + `NativeRecipeResolver`（见 `profession_crafting_design.md` §10）。
> - **长期任务/契约（原「无」）**：已新增 `LongTermAgenda`（debt/acquire/deal/generic）+ `AgendaParser` + 好感度 `playerReputation`。
> - **仍缺失（与本文一致）**：繁衍系统、村民间交易经济、通用采集（挖矿/伐木/钓鱼）、天气反应、死亡记忆、MotivationSystem、VillageMemory 共享知识等。

## 一、当前项目概览

**技术栈**: Minecraft 1.16.5 + Forge 36.2.42 + Java 8 + LLM (OpenAI/Anthropic/Ollama/Gemini)

**核心设计**: 将原版村民改造为 Stanford Generative Agents 风格的自主 AI Agent，通过 LLM 驱动认知、决策与社交。

**源码规模**: 44 个 Java 文件，涵盖感知、决策、行为、社交、经济五大子系统。

## 二、用户期望的六大能力 vs. 当前实现

### 1. 主动采集 — 部分实现 (30%)

**已有**: 农民自动收割成熟作物、种植种子、等待掉落物拾取
**缺失**:
- **通用采集系统**: 当前只有 farmer 职业能采集农作物，其他职业无法挖矿、伐木、采集资源
- **资源感知**: 村民不知道哪里有矿石、树木、水源——缺乏资源定位能力
- **工具使用**: 不会使用镐挖矿、斧砍树、桶取水
- **主动需求驱动采集**: 当饥饿时不会主动去种地或找食物，只是被动吃已有的食物

**建议实现**: 新建 `GatheringAction.java`，按职业扩展采集类型（矿工挖矿、木匠伐木），并新建 `ResourceScanner.java` 扫描周围资源分布

### 2. 制作 — 基础实现 (40%)

**已有**: 走到工作台→工作200tick→按配方表制作第一个可制作的物品
**缺失**:
- **配方表过少**: RecipeRegistry 只有5个配方（木棍、铁剑、铁镐、铁斧、铁锭）
- **无主动制作意图**: 村民不会因为"需要面包"而主动制作面包
- **无材料收集循环**: 不会因为缺铁而主动去挖矿
- **无食物制作**: farmer 没有面包、蛋糕等食物配方
- **无建筑方块制作**: 不会制作木板、石砖等建筑材料

**建议实现**: 扩展 RecipeRegistry 至 20+ 配方，增加"材料不足→生成采集目标→收集→返回制作"的完整循环

### 3. 沟通 — 基本完整 (70%)

**已有**: 村民间LLM对话、玩家聊天GUI、自发内心独白、玩家接近问候、关系5档影响语气、八卦传播
**缺失**:
- **无协作沟通**: 村民不会通过对话协调分工（"你去挖矿，我来种地"）
- **无知识共享**: 一个村民发现矿洞不会告诉其他村民
- **无请求/帮助系统**: 村民不会向其他村民请求帮助或物品
- **无情绪表达行为**: 对话中有情绪文本但无表情/动作表现

**建议实现**: 新建 `VillageBulletinBoard.java` 共享知识系统，扩展对话系统支持请求/承诺/分工

### 4. 交易 — 玩家向完整，村民间缺失 (50%)

**已有**: 玩家与村民LLM议价交易、装备可交易、性格影响交易决策
**缺失**:
- **村民间交易**: 两个村民之间不会自主交易（铁匠用剑换农民的面包）
- **市场价格系统**: 没有统一的物品价值体系，交易完全靠LLM即时判断
- **商铺/交易点**: 没有物理交易场所
- **库存驱动交易**: 村民不会因缺少某物而主动寻找有该物的村民交易

**建议实现**: 新建 `VillagerTradeSystem.java` 处理村民间自主交易，引入 `ItemValueTable.java` 基础价值表

### 5. 建造 — 未实现 (5%，仅有设计文档)

**已有**: `docs/building_perception_design.md` — 详细的关系型建筑结构感知方案（体素化/自由空间/房间检测/门窗识别）
**缺失**:
- **建造系统本身**: 完全没有放置方块的代码
- **建筑蓝图**: 没有房屋/农场/道路的设计模板
- **材料收集→建造循环**: 不会收集木材/石头后去建造
- **建筑感知**: StructureParser 设计文档已有但未编码
- **协作建造**: 多人分工建造大型建筑

**建议实现**: 先实现 `StructureParser.java`（按设计文档），再实现 `BuildingAction.java` + `BuildingBlueprint.java` 蓝图系统

### 6. 繁衍 — 完全未实现 (0%)

**已有**: 无
**缺失**:
- **配偶选择**: 基于关系值/性格匹配选择伴侣
- **住房需求**: 需要有足够的床位/房屋才繁衍
- **后代生成**: 新村民的生成、遗传父母特征
- **幼年成长**: 幼年村民的成长阶段与学习
- **家庭关系**: 父母/子女/兄弟姐妹的关系追踪

**建议实现**: 新建 `ReproductionSystem.java`，扩展关系系统支持家庭关系，需要建造系统提供住房

## 三、缺失模块详细分析（按优先级排序）

### P0 — 实现自主意识涌现的核心前提

#### 3.1 LLM 行动决策器 (LLM Action Decision Engine)

**现状**: `generateNewGoals()` 用纯随机数生成目标，`processGoals()` 中 craft/trade/socialize 的执行函数全是 TODO 空壳

**需要**: 一个基于 ReAct (Reasoning + Acting) 模式的 LLM 决策器：
1. **观察**: 汇总环境感知 + 需求状态 + 记忆 + 关系
2. **推理**: LLM 分析当前最紧迫的需求和最优行动
3. **行动**: 输出结构化行动指令（JSON），由 ActionExecutor 执行
4. **反思**: 行动完成后记录结果到记忆

```
输入 → LLM: {环境摘要, 需求状态, 心情, 最近记忆, 当前目标, 物品栏, 关系}
输出 ← LLM: {"action": "gather", "target": "iron_ore", "reason": "需要铁锭制作工具"}
```

**关键文件**: 新建 `LLMDecisionEngine.java`，重写 `VillagerAgentManager.generateNewGoals()` 和 `processGoals()`

#### 3.2 欲望/动机系统 (Desire & Motivation System)

**现状**: 只有饥饿和疲劳两个生理需求，缺乏心理层面的驱动力

**需要**: 仿照马斯洛需求层次的动机系统：
- **生理层**: 饥饿(已有)、疲劳(已有)、安全(战斗已有但无恐惧)
- **归属层**: 社交需求(对话已有但无孤独感)、家庭需求
- **尊重层**: 被认可需求、地位追求
- **自我实现**: 好奇心驱动的探索、技能精进、创造欲

每个动机产生压力值，压力高的动机会优先转化为行动目标。

**关键文件**: 新建 `MotivationSystem.java`，扩展 `VillagerAgentData` 增加 desire 字段

#### 3.3 建筑结构感知 (Structure Perception)

**现状**: 有 350 行的详细设计文档 (`docs/building_perception_design.md`)，但零行代码

**需要**: 按设计文档实现 `StructureParser.java`：
- 体素化 + 2.5D 柱列表示
- 自由空间膨胀 → 房间连通分量
- 墙/顶/地边界方向分类
- 门/窗连通性判定
- 柱检测
- 输出结构化 JSON 喂给 LLM

这是实现建造、室内导航、住房分配的前提。

### P1 — 实现自主生活的关键能力

#### 3.4 通用采集系统 (Universal Gathering System)

**现状**: 只有 farmer 能收割/种植农作物

**需要**: 按职业扩展采集能力：
- **矿工**: 找矿脉→走过去→用镐挖→拾取矿石
- **伐木工**: 找树→走过去→用斧砍→拾取原木→补种树苗
- **渔夫**: 找水→钓鱼→拾取鱼
- **牧民**: 找动物→繁殖→剪羊毛/挤奶→屠宰获取肉
- **通用**: 拾取地面物品(已有 `ItemAttractionSystem`)

**关键文件**: 新建 `MiningAction.java`, `WoodcuttingAction.java`, `FishingAction.java`

#### 3.5 建造系统 (Building System)

**现状**: 零实现

**需要**:
- **蓝图系统**: 预定义房屋/农场/围墙/道路模板（坐标偏移 + 方块类型列表）
- **选址逻辑**: 基于地形平坦度、距村庄中心距离、不与其他建筑冲突
- **材料检查**: 确认物品栏有足够材料，否则生成采集目标
- **放置方块**: 走到目标位置→逐层放置方块
- **协作建造**: 大型建筑可分配给多个村民同时建造

**关键文件**: 新建 `BuildingAction.java`, `BuildingBlueprint.java`, `BlueprintRegistry.java`

#### 3.6 导航增强 (Enhanced Navigation)

**现状**: 使用原版 A* 寻路，不支持室内导航、长距离寻路、避障优化

**需要**:
- **室内导航**: 配合 StructureParser，知道门在哪、房间在哪
- **长距离寻路**: 超过50格的目标需要分段寻路 + checkpoint
- **地形感知**: 绕过悬崖、岩浆、水域
- **路径缓存**: 记住常用路径（家→农场→工作台）

**关键文件**: 新建 `VillagerNavigator.java` 包装原版寻路

#### 3.7 村民间交易系统 (Villager-to-Villager Trade)

**现状**: 只有玩家-村民交易

**需要**:
- **自主交易触发**: 当村民A需要某物且村民B有该物时发起交易请求
- **物物交换**: 不使用货币，基于 ItemValueTable 的等价交换
- **交易对话**: 交易前有一段简短的议价对话
- **交易记录**: 记入双方记忆，影响关系

**关键文件**: 新建 `VillagerTradeSystem.java`, `ItemValueTable.java`

#### 3.8 繁衍系统 (Reproduction System)

**现状**: 零实现

**需要**:
- **配偶选择**: 关系值 > 60 + 相反性格偏好 + 都有住房
- **繁衍条件**: 食物充足 + 村庄人口未达上限 + 有空床
- **后代生成**: 生成新的幼年村民，遗传父母性格混合 + 随机变异
- **幼年阶段**: 幼年村民跟随父母学习，成长后获得职业
- **家庭关系**: 扩展关系系统增加 family 关系类型

**关键文件**: 新建 `ReproductionSystem.java`, 扩展 `VillagerAgentData` 增加 age/family 字段

### P2 — 增强涌现深度的模块

#### 3.9 天气反应系统 (Weather Response)

**现状**: AI_AGENT_GUIDE.md 中列为 Pending

**需要**:
- 下雨时寻找遮蔽物（配合 StructureParser 找最近建筑）
- 雷暴时恐惧心情加剧，拒绝外出
- 雨天取消户外活动，改为室内制作/社交
- 雪天在寒冷生物群系减少外出

#### 3.10 死亡与遗产系统 (Death & Legacy)

**现状**: 村民死亡只掉落物品，无记忆传递

**需要**:
- 附近村民产生悲痛记忆，心情变为 DISTRESSED
- 死亡村民的物品可被亲属继承
- 死亡事件记入村庄历史
- 有贡献的村民获得纪念（墓碑/雕像）

#### 3.11 社会角色系统 (Social Roles)

**现状**: 只有职业，无社会阶层

**需要**:
- **村长**: 关系值最高/年龄最大的村民，负责协调分工
- **长老**: 经验丰富的村民，传授知识
- **教师**: 教导幼年村民技能
- **学徒**: 跟随成年村民学习

角色影响日程规划和对话语气。

#### 3.12 共享知识/村庄记忆 (Village Shared Knowledge)

**现状**: 每个村民的记忆是独立的

**需要**:
- **村庄公告板**: 所有村民可读写的共享信息（矿洞位置、危险事件、丰收信息）
- **事件传播**: 重要事件通过社交网络传播（已部分实现八卦传播）
- **村庄历史**: 记录建村以来的重大事件

**关键文件**: 新建 `VillageMemory.java` 作为全局共享状态

#### 3.13 工具使用系统 (Tool Usage System)

**现状**: farmer 自动装备锄头，战士自动装备武器，但不会主动使用其他工具

**需要**:
- 挖矿时自动装备镐
- 伐木时自动装备斧
- 战斗时自动装备剑/斧
- 水域交互时装备桶
- 工具耐久度追踪与修复/替换

#### 3.14 食物获取系统 (Food Acquisition)

**现状**: 饥饿时只检查物品栏吃已有食物，不主动获取

**需要**:
- 饥饿值 < 30 时生成"获取食物"高优先级目标
- 按职业选择获取方式：farmer 种地、渔夫钓鱼、猎人打猎
- 食物烹饪：将生肉烤熟、将小麦做成面包
- 食物储存：将多余食物存入箱子

#### 3.15 成长与衰老系统 (Growth & Aging)

**现状**: 村民创建后永远不变

**需要**:
- **幼年** (0-3天): 跟随父母，学习技能，不能工作
- **成年** (3-30天): 可工作、可繁衍、战斗
- **老年** (30+天): 行动缓慢，但智慧高，担任长老角色
- 技能随时间提升：重复某项工作越多效率越高

#### 3.16 文化传承系统 (Cultural Inheritance)

**现状**: 无

**需要**:
- 父母的技能/知识部分传给后代
- 村庄传统形成（某些行为模式通过模仿传播）
- 故事/历史通过口口相传保留在村庄记忆中
- 世代交替后村庄文化可能演变

## 五、关键技术约束与建议

### LLM 调用成本控制
- 当前每个村民每 100 tick (5秒) 触发一次慢速 tick
- 日程规划、对话、思考、问候各产生 1 次 LLM 调用
- 10 个村民同时在线时峰值可达 ~20 次/分钟 LLM 调用
- **建议**: 行动决策器使用轻量级 LLM (gpt-4o-mini / gemini-flash)，复杂推理才用大模型
- **建议**: 引入 LLM 响应缓存，相似场景复用结果

### 性能优化
- `findVillagerEntity()` 每次通过 `serverWorld.getEntity(uuid)` 查找，建议缓存 Entity 引用
- 空间记忆 512 chunk 上限可能不够，建议分区域存储
