# 能力、制作与经济

核对日期：2026-10-23。行为执行使用 [主循环](事件驱动大脑与资源订单.md)，物品不足的处理见 [失败恢复](失败驱动重规划.md)。

## 能力与职业

`CapabilityPool` 是每个 agent 的能力表，包含 FARMING、FISHING、SMITHING、BREWING、ENCHANTING、CRAFTING、GATHERING、SOCIAL、COMBAT。它存每项 XP 和最后练习日，通过 `CapabilityLevelTable` 推导等级，并随 agent NBT 保存。

职业、能力、资源角色分别表达工作身份、技能水平和资源订单承接资格。`ResourceProfession` 的伐木工/矿工独立保存；原版职业由 POI 与村民数据表示。初始化与授职的能力赋值入口在 `VillagerAgentData` 和 `VillagerEventHandler`，配方资格由实际能力与目录查询决定。

练习/交流通过 `addXp` 更新 XP 和练习日；每天的慢更新执行衰减、原版交易等级同步和解锁表刷新。衰减有 2 天宽限，之后按 `max(0, 1-(effectiveDays/rustDays)^2)` 乘当前 XP；`rustDays` 默认 14。没有练习日期的条目跳过衰减。原版等级换算方法为 `max(0,min(5,(level-1)/2))`，最终实体写入规则看 `syncVanillaTradeLevel`。

`VillagerProficiency` / `ProficiencyCapability` 是另一套 Forge Capability XP 接口。修改能力门控时从 `CapabilityPool` 和实际调用方定位；两套数据的消费者分别核对。

## 行为资格与配方

`BehaviorCatalog` 提供门控元数据，`BehaviorExecutor.TYPE_TO_SKILL` 给出可执行目标映射，技能 `canHandle` 决定本次执行资格。农耕的 maintain/reclaim 是 `FarmSkill` 内的处理阶段；其能力与工具要求在技能方法体内判断。

`DeterministicPlanGenerator` 提供职业行为池查询与制作目标选择，`RoutineScheduler` 调用这些方法维护候选。候选产生与 Utility 评分是不同阶段；运行时评分规则集中在主循环文档。

`SkillCraftCatalog` 汇集职业配方、通用配方和按能力解锁的条目；`UnlockedRecipes` 保存每村民可用项。`craft_unlocks.json` 提供技能解锁配置。配方可制作必须同时满足解锁和配方解析。

`NativeRecipeResolver.resolveRecipe` 优先解析原版配方，使用 `CustomRecipeRegistry` 作为自定义配方路径，输出统一的 `ResolvedRecipe`。`consumeAndProduce` 核对并消耗材料后产出物品，`missingMaterials` 提供缺料查询。`CraftSkill` 负责制作目标的工作步骤；`AcquireItemSkill` 还支持现场材料转换。

自定义配方服务于原版无配方物品等情况。职业目录中存在大师附魔资格等属性，具体装备产出由执行侧读取。增加物品时同时检查解锁表、原版/自定义配方、材料供给及完成时的库存变化。

## 交易与物资

- `TradeRequestPacket` 处理玩家交易请求；`VillagerTradeScreen`、`TradeResultPacket` 负责界面与结果。估价依据物品价值表和村民个人估值，成交以服务端检查及实际库存转移为准。
- `VillagerEconomySystem` 扫描职业必需品和供需，维护现货交易与生产需求。现货配送进入 `deliver_trade`，由 `TradeDeliverySkill` 执行，包含绿宝石结算。
- `VillageSignalBoard` 发布 `TRADE_WANT/TRADE_HAVE` 等即时供需信号；资源订单在 `WorkOrderBook` 维护需求与租约。原料订单的协作供给与现货交易的结算各有入口。
- `InventoryTransfer` 按实际容纳数量移交，满背包和部分交付需保留未转移物品。
- `JobStarterItems` 定义首次授职物资及 restock 需求。restock 提交物资请求，资源角色首次授职可领取基础工具。

`RecipeRegistry`、`CraftingAction`、`ActionExecutor` 等类在树中仍可见；活跃目标制作从 `CraftSkill`、`SkillCraftCatalog`、`NativeRecipeResolver` 定位。网络包注册、类存在和客户端实际发送是不同层面的证据。

数据文件与配置入口见 [配置与运行](配置与运行.md)。
