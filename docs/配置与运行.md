# 配置与运行

核对日期：2026-10-23。版本取自 `gradle.properties`，命令取自 `VillagerAgentCommand`，配置默认值取自 `ModConfig`。

## 构建与启动

Minecraft 1.16.5、Forge 36.2.42、official 1.16.5 映射；`build.gradle` 的 Java toolchain 为 8。在项目根目录使用 Windows wrapper：

```powershell
.\gradlew.bat compileJava --console=plain
.\gradlew.bat check --console=plain
.\gradlew.bat build --console=plain
.\gradlew.bat runClient
```

构建产物在 `build/libs/`，安装到对应 Forge 实例的 `mods/`。依赖已缓存时可追加 `--offline`。`check` 包含订单和目标退出规则检查；测试范围见 [调试手册](DEBUG_VERIFICATION.md)。

## 配置文件分工

行为开关、范围与节奏在游戏目录 `config/villageragent-common.toml`。`ai/config/VillagerAgentConfigDir` 管理 `config/villageragent/` 外置数据，缺文件时使用内置默认资源初始化；加载与重载能力按各读取器核对。

| 数据 | 内置入口 |
|---|---|
| 自定义配方 | `src/main/resources/villageragent/custom_recipes.json` |
| XP 与等级 | `src/main/resources/villageragent/proficiency.json` |
| 技能配方解锁 | `src/main/resources/villageragent/craft_unlocks.json` |
| 本地台词 | `src/main/resources/villageragent/default_chat_lines.json` |
| 经济价值、来源、职业必需品 | `src/main/resources/data/villageragent/economy/` 中三个 JSON |

## 常用开关

| 配置键 | 默认 | 当前用途 |
|---|---|---|
| `enable_ai_agents` | true | agent 总开关 |
| `agent_think_interval` | 100 | 慢感知与候选维护间隔，单位 tick |
| `enable_world_interaction` | true | 世界交互 |
| `economy_enabled` | true | 经济与物资业务 |
| `enable_villager_social` | true | 村民社交 |
| `enable_villager_thoughts` | false | 可选内心独白 |
| `enable_auto_pickup` | true | 掉落物拾取 |
| `enable_building` | true | 建造路径 |
| `brain_log_enabled` | true | 决策/执行日志 |
| `enable_debug_overlay` | false | 调试可视化 |
| `debug_render_range` | 64 | 可视化范围 |
| `debug_show_hud/buildings/seeds/field` | true | 分别控制 HUD、建筑、种子、距离场（完整键均以 debug_show_ 开头） |

`enable_daily_schedule`、`behavior_executor_interval_ticks`、`harness_drive_daily_goal` 在配置定义中存在；当前主循环为需求与机会驱动、逐 tick 执行，Harness daily 入口没有调用方。配置界面显示某项时，应追踪消费点再判断其运行效果。

## 命令

根命令支持 `/va` 和 `/villageragent`，使用游戏内补全查看参数：

```text
/va config list
/va config set debugoverlay true
/va llm status
/va info
/va orders
/va occupation lumberjack
/va occupation miner
/va occupation none
/va request minecraft:oak_log 8
```

occupation、request 与 orders 面向附近受管村民的资源工作场景，具体含义见主循环文档。`/va goals clear` 会清除目标；调试时有意使用。`/va reload` 的覆盖范围以命令实现和读取器为准。

## 可选 LLM

`llm_api_type` 支持 openai、anthropic、ollama、gemini。当前默认 type 为 openai，URL 为 `https://api.deepseek.com/v1/chat/completions`，model 为 `deepseek-chat`，key 为空。使用时配置服务实际支持的 URL、模型和凭据，可通过 `/va llm apitype/model/apiurl/apikey` 子命令设置，再检查 status。

规则链路可在未配置 LLM 时运行。`harness_timeout_ms` 默认 15000，`harness_circuit_failures` 默认 3，`harness_circuit_cooldown_ticks` 默认 1200；这些参数作用于使用 `LLMGuard` 的调用路径。
